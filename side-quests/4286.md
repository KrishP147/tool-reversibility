Thanks for reproducing this. I looked at where the mismatch comes from, and the runtime and the public type disagree:

- `ToolRouterSession.authorize()` (`ts/packages/core/src/models/ToolRouterSession.ts`, around L444-453) accepts `experimental: { accountType?, aclConfigForShared? }` and sends it on the wire.
- `composio.create()` returns the `Session` interface, and its `authorize` is typed as `ToolRouterAuthorizeFn` (`ts/packages/core/src/types/toolRouter.types.ts` L533-536), which only allows `{ callbackUrl?, alias? }`. The published 0.18.0 `.d.mts` has the same split, and `next` still does.

The sample is `installAuthorize` in `docs/lib/slack-bot-build.ts` (L346-358), which renders on `/examples/general-agent-with-pi`.

Which one is intended?

1. **Shared accounts from `session.authorize()` are supported**, and the type is behind. The fix is to widen `ToolRouterAuthorizeFn`:

   ```ts
   options?: { callbackUrl?: string; alias?: string; experimental?: { accountType?: ConnectedAccountType; aclConfigForShared?: ConnectedAccountAclConfig } }
   ```

   plus a type test and a patch changeset for `@composio/core`.

2. **Shared accounts shouldn't be created through a session**, and the sample is ahead. The fix is to drop the `experimental: { accountType: 'SHARED' },` line from the sample and create the SHARED connection with `composio.connectedAccounts.link(..., { experimental: { accountType: 'SHARED' } })` instead.

My guess is option 1, since the class already implements it and its JSDoc documents it. I'm happy to open a PR for whichever you choose.
